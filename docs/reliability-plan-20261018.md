# 可靠性审查与修复计划（2026-10-18）

目标：在现有单进程、单 Worker、SQLite 架构内修复可复现的行为错误，增强项目的可验证性。保持现有 HTTP API 与默认离线演示能力。

基线：提交 `5f9b156`；原目录同版本测试已在本次对话执行，34 passed、1 xfailed。原目录未跟踪的 `docs/04-架构图解.md` 属于用户既有材料，不改动。

## 1. 返工与交付门禁

- 用回归测试复现提示词故障仍只重跑 generation 的空转。
- 按 Finding 归属重跑失败镜头的 prompt，再生成受影响的素材；实际 LLM 请求接收反馈。
- 保留已通过镜头的提示词与素材，不因局部返工被覆盖。
- 每轮复检执行 BLOCKER 门禁；出现阻断问题不得进入 compose。
- 复检发现已验收素材缺失时，明确阻止交付，不伪造新的素材掩盖问题。
- 移除已修复用例的 xfail，补充恢复成功、重试耗尽、反馈传入与局部更新测试。

## 2. 任务生命周期与审计

- 核实异常路径、导出失败与成功状态发布的顺序，统一失败收尾。
- 成功状态只在交付包准备好之后发布；导出失败不能保留虚假的成功状态。
- Worker 停止后再关闭数据库，避免长任务仍写入已关闭连接。
- 评估启动时遗留 PENDING/RUNNING 的有限恢复策略；不自动重复收费生成，不引入多进程调度承诺。

## 3. 外部依赖与运行模式

- 核实 Provider 回退后的配置与健康检查是否反映实际运行模式。
- 核实 LLM Tool Calling 的镜头范围、参数和关键帧依赖；只修复有可重复证据的问题。
- 保持所有验证离线，不调用付费 API。
