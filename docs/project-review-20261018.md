# AIGC 工作流项目评估与优化记录

评估日期：2026-10-18。范围为本地源码、测试、PRD 与 README；未调用真实 LLM 或外部图片服务。原始基线为 `5f9b156`。

## 项目判断

这是一个有真实业务来源、能够跑通的个人工程原型。最有价值的部分是结构化产物契约、任务与镜头状态机、独立 Provider、失败留痕与可离线执行的测试。固定五阶段编排符合当前需求，不必为了“Multi-Agent”标签增加自主规划或代理间对话。

主要短板是边界行为的正确性：返工是否真的改变故障输入、成功状态是否意味着交付齐备、服务退出是否保留一致状态、模型是否只能操作被授权的镜头。这些问题应先于扩大生成能力处理。

## 本轮修复范围与验收

详见 [可靠性修复计划](reliability-plan-20261018.md)。下表问题均已实现修复，并分别完成需求符合性与代码质量复核；最终原目录集成测试结果见下方验证记录。

| 优先级 | 原始问题 | 验收目标 |
|---|---|---|
| P1 | 提示词失败仍仅重跑素材生成，重试不能改变输入 | R1/R2/R5 定向返工提示词并重新生成相关素材，保留其他镜头 |
| P1 | BLOCKER 仅在第一轮质检后检查 | 每轮复检后都执行门禁，阻断问题不进入剪辑 |
| P1 | 任务先报成功再导出；磁盘异常后仍显示成功 | 交付包就绪后才发布成功，异常保留明确失败与审计线索 |
| P1 | 局部返工时模型能调用其他镜头工具或使用错误关键帧 | 执行前限制本轮镜头，视频只使用本镜头成功生成的关键帧 |
| P1 | Worker 仍运行时数据库可能被关闭 | 等待当前任务结束后再关闭数据库 |
| P2 | 重启后 PENDING 丢失调度、RUNNING 永久悬挂 | 恢复待执行任务，中断任务明确失败，不自动重复外部生成 |
| P2 | Provider 回退但健康检查仍显示请求的 Provider | 返回实际运行配置 |
| P2 | API 支持八镜头而 Mock 只有三镜头，真实脚本未校验数量和重复 ID | 支持请求范围并验证输出契约 |
| P2 | JSON 解析误将字符串中的花括号计为结构 | 合法 JSON 字符串可以被正确解析 |
| P2 | 漏镜补做丢失英文提示词映射 | 首轮与补做轮采用同一提示词映射 |

P1 表示可能错误交付、错误发布成功或破坏任务状态；P2 表示特定配置、输入或重启场景下的功能错误。这是本项目的修复排序，不代表安全漏洞评级。

## 后续优化顺序

1. **真实内容质量与演示闭环**：补齐真实 MP4 路径的字幕；明确当前质检检查的是文本规则、文件与时长字段，并没有判断画面与商品是否一致。准备固定主题、可重复播放的示例及失败案例。让渲染层返回实际转场策略和输出时长，修正目前 `approx_duration_s` 未扣转场重叠、退回普通拼接仍报告 `xfade-fade` 的元数据偏差。
2. **可观察的任务成本**：在现有步骤记录上汇总耗时、重试次数、失败分类；真实调用启用后记录供应商返回的 token/计费信息，区分实际费用与估算。不需要先引入独立监控平台。
3. **质量评测集**：为不同商品、提示词缺失、图片缺失、外部服务失败建立固定用例。衡量完整交付率、人工可用率、平均返工次数和人工验收耗时；离线 Mock 测试结果不能替代真实生成质量。
4. **运行部署边界**：当前以本地、单进程、单 Worker 为范围。公开服务之前补齐鉴权、用量限额、资源清理和可访问产物下载；只有实际并发与吞吐需求出现后再考虑持久队列、分布式锁或独立 Worker。
5. **生成能力**：真实图生视频 Provider 是独立后续任务，接入时需要核实供应商接口、超时、轮询、成本与错误分类。当前接口占位不能表述为已经具备生产接入能力。

## 文档与个人展示建议

- 项目描述可用“状态机驱动的 AIGC 视频工作流原型”；突出故障定位、局部返工与交付一致性，而非代理数量。
- README 的能力表应同时说明实现和限制，避免“预留接口”等同于“已支持”。
- 不以测试数量或架构评审轮数代替成果；展示一个可复现故障、修复、回归测试和最终行为即可说明工程判断。
- 所谓“合规门禁”目前是有限词表规则检查，不能据此宣称完成全面内容审核。

## 保留限制

无真实视频模型接入，无视觉语义质量评估，无配音与 BGM；真实镜头 MP4 拼接路径的字幕尚未补齐。外部服务当前可用性与成本未联网验证。生产使用能力、吞吐性能和真实内容可用率均不能由本轮离线测试推导。
