> 目的：动手前先看成熟方案，借鉴架构思路、避免重复造轮子。调研日期 2026-09-04。

## 1. 调研对象与结论

| 项目 | 定位 | 关键机制 | 本项目借鉴点 |
|---|---|---|---|
| **MoneyPrinterTurbo**（harry0703，GitHub 约 7 万星） | 一站式 AI 短视频生成：主题→LLM 脚本→素材匹配→字幕→配音→BGM→合成 | 提供 AI Agent / WebUI / API / CLI 四种使用方式；代码按 controller/service/model 分层；支持 100+ LLM 与 9 种 TTS，可批量 | ① 分层架构（API 层/服务层/模型层分离）② API-first 的对外形态 ③ Provider 全部配置化可替换 |

## 2. 共识路径（社区普遍做法）

所有成熟项目的主链路高度一致：

```
主题/商品 → LLM 脚本 → 分镜/提示词 → 素材生成/检索 → （质检）→ 合成成片
```

本项目 v1 覆盖到"素材生成+质检"，成片合成留给 v2——与共识路径一致，不算发明新流程。

## 3. 本项目与它们的差异化

上述项目多是**内容生产工具**（重点在"出片"）；本项目是**任务系统工程演示**（重点在状态机、调度、重试、留痕、可测试性）——出片质量靠 Mock/真实 Provider 保证，而工程骨架才是核心交付。两者不冲突：本项目 v2 完全可以把 MoneyPrinterTurbo 式的合成能力作为一个 Provider/Agent 挂进来。
